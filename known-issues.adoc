Les problèmes connus recensent les dysfonctionnements susceptibles de vous empêcher d'utiliser correctement cette version du produit.

Les problèmes connus suivants affectent la version actuelle :



== VolumeSnapshots n'atteignent pas l'état ReadyToUse

[WARNING]
====
Il existe un problème connu avec le `csi-snapshotter` sidecar. Dans toutes les versions de Kubernetes, VolumeGroupSnapshots `v1beta1` empêche VolumeSnapshots d'atteindre l' `ReadyToUse` état.

====
Deux solutions de contournement sont disponibles :

. Supprimez les CRD VolumeGroupSnapshots pour désactiver VolumeGroupSnapshots, puis réinstallez Trident.
. Installez VolumeGroupSnapshots `v1beta2` et `snapshot-controller` la version 8.4.0 ou ultérieure, puis réinstallez Trident. VolumeGroupSnapshots ne fonctionnent pas sur les versions de Kubernetes antérieures à la v1.34.




== La restauration des sauvegardes Restic de fichiers volumineux peut échouer

Lors de la restauration de fichiers de 30 Go ou plus à partir d'une sauvegarde Amazon S3 effectuée avec Restic, l'opération de restauration peut échouer. Comme solution de contournement, sauvegardez les données en utilisant Kopia comme outil de déplacement de données (Kopia est l'outil de déplacement de données par défaut pour les sauvegardes). Consultez  https://docs.netapp.com/us-en/trident/trident-protect/trident-protect-protect-apps.html["Protégez les applications à l'aide de Trident Protect"^] pour obtenir des instructions.
